# Report Schema Versioning — Prompt 01

All Prompt 01 report surfaces (Rust `sdk`, Python, C ABI) return the **same
versioned JSON envelope**. This document is the contract.

## Envelope

```json
{
  "schema_version": 1,
  "kind": "<report kind>",
  "report": { ...report-specific fields... }
}
```

- `schema_version` — the **envelope** version, exposed as
  `oxide_engine::REPORT_ENVELOPE_VERSION` (Rust), `oxide.__report_envelope_version__`
  (Python), and `oxide_abi_version()` (C). Currently `1`.
- `kind` — a stable string identifying the report (see table below). Consumers
  should switch on `kind`, not on structural sniffing.
- `report` — the report payload. Most engine report structs additionally carry
  their **own** inner `schema_version` (e.g. `SecurityReport.schema_version`,
  `StandardsValidationReport.schema_version`, `ChunkSet.schema_version`); those
  evolve independently of the envelope.

Output-producing operations return the produced bytes separately (the second
tuple element in Rust, an `OxideBuffer` in C, the first tuple element in Python)
plus an envelope whose `kind` ends in `_report`.

## Compatibility rules

- **Additive changes** (new optional fields) do **not** bump `schema_version`.
- **Breaking envelope changes** (renaming `report`/`kind`, changing nesting) bump
  `REPORT_ENVELOPE_VERSION`, and `oxide_abi_version()` /
  `oxide.__report_envelope_version__` move in lock-step.
- Inner report structs bump their own `schema_version` for breaking payload
  changes, independent of the envelope.

Prompt 12 adds
`report.prompt12_prepress_cmm_device_link_separation_plates` to
`feature_report` and corresponding additive fields to color/prepress reporting.
This is an additive payload change and does not bump `REPORT_ENVELOPE_VERSION`.

## Determinism & parity

- The same document produces byte-identical `report` payloads across Rust,
  Python, and C ABI (proven by comparing the three smoke JSON artifacts in
  `target/prompt01-binding-core/`).
- `canonicalize_report` output bytes are deterministic for a fixed
  `date_epoch` (the SDK/Python tests assert two runs are byte-equal and
  `output_sha256` matches).
