## Additional renderer algorithms and missing implementations discovered during repository audit

1. **Raw-operation retained high-level replay:** `DisplayOp::{StateOp,NativeTextOp,NativeImageXObject,NativeShadingOp,NativePatternPathOp,NativeInlineImage,NativeFormXObject}` retain `ContentOperation` values rather than compiled payload IDs (`render/display_list.rs:82+`). This defeats the required packed hot/cold split and must be replaced, not merely documented.
2. **Display-list identity is underspecified:** `RenderDocumentCache::display_list_key(page_number, dpi)` (`render/page_renderer.rs`) contains no document revision or render contract; local edits cannot safely use narrow cache invalidation.
3. **Progressive implementation is a tile iterator, not the requested lifecycle:** `render/progressive.rs` has no pause/resume/cancel/close state transitions or dirty-region/fallback report.
4. **Cache policy is mixed:** Some image/mask/raster caches account bytes, while Form/pattern/font resolver/display-list/transparent-group maps are plain `HashMap`s (`RenderDocumentCache` fields). This is an architectural resource-bound gap.
5. **Backend plan and complete caller surface ownership are still incomplete:** `RenderContract` and CLI raw surfaces now validate caller-owned raster layouts through the engine, but `CpuRenderDevice`/`PixelBuffer` are still internal execution constructs and there is no complete backend-neutral surface interface for every binding and policy field.
6. **Direct official PDFium C/C++ harness source now exists:** `tools/pdfium-harness` provides CMake, a direct C renderer, one/all-page selection, DPI, page box, matrix, clip, output dimensions, annotation/form flags, raw BGRA/BGRx output, FNV output hash, worker-count metadata, JSONL typed failures, and a version manifest. Local SDK build/runtime validation is intentionally deferred because this task cannot download or provision PDFium.
7. **Binding raster capability differs materially:** C/Python/WASM only expose limited encoded rendering; .NET/Java have no general raster render surface; server adds cancellation but no full contract.

No performance conclusion follows from this inventory. It is a source-based implementation map for the next steps of this task.
