## Additional renderer algorithms and missing implementations discovered during repository audit

1. **Retained high-level payload typing:** `DisplayOp::StateOp` now stores typed `GraphicsStateDescriptor` values, `DisplayOp::NativePatternPathOp` stores typed `PatternPathDescriptor` values, `DisplayOp::NativeTextOp` stores typed `RetainedTextOp` values, `DisplayOp::NativeInlineImage` stores typed params/data payloads, `DisplayOp::{NativeImageXObject,NativeShadingOp,NativeFormXObject}` retain typed resource names instead of cloned raw `Do`/`sh` operations, and `PackedColdTables` is diagnostics-only with no raw `ContentOperation` payload vectors. When packed compilation has a resource table, missing retained Image XObject, Form XObject, and named shading resources now become typed `PackedCompileRefusal` descriptors instead of runtime name lookups. The remaining gap is no longer raw retained display-command payloads; it is the broader source-program `Vec<ContentOperation>` representation plus full backend-specialized hot/cold arena closure.
2. **Display-list retained source identity remains partial:** supported source-editing text transactions now carry concrete changed object/page sets into render invalidation, scene `geometric_block`/`semantic_document` text transactions route through the canonical TextReflow preview/apply paths instead of a blanket stub, forward compact request region/flow/layout/review options, then convert source refs, affected pages, dirty regions, typed refusals, and inverse metadata back into the EditingTransactions invalidation envelope, and advanced-editing Link/Ink annotation updates now emit structured render write-set refs, changed/created object refs, affected pages, and page-space dirty regions. DocumentSubsystems AcroForm actions and secure-mutation incremental form fills now expose structured field/widget/AP render write-set refs, affected pages, and dirty widget rectangles where live widget appearances change. PDF refs, structured `[object, generation]`/`{object_number, generation}`/`{ref}` refs, and `object-*`/`stream-*` source IDs map through canonical object identities, report dirty rectangles can convert to render tiles when callers provide the active viewport/grid, explicit dirty tiles/source-to-tile graph edges can evict exact raster tiles without pruning full page artifacts, source-only mapped transactions use page-artifacts-plus-exact-tiles invalidation with safe expansion when source coverage is incomplete, and explicit dirty-tile plans with affected pages prune page-scoped retained artifacts without expanding raster invalidation to every recorded page tile. `PageResources` preserves indirect font/color-space/ExtGState source refs, and raster-cache insertion scans bounded retained font-backed text, color-space-backed paint/text, ExtGState-backed paint/text/inline-image, XObject/Form and shading object graphs, pattern-path, and pattern-painted text ops to record tile edges where canonical resource source IDs exist, including bounded transitive refs for retained font, color-space, ExtGState, pattern, XObject/Form, and shading resource objects. `RenderDocumentCache` now remembers canonical object-number/generation identities and cache markers for mapped source IDs; cache-plan application also maps string and structured nested render write-set refs from SDK/server/report envelopes through those remembered identities before pruning source-bound decoded-image, scaled-image, SMask, mesh-shading, Form-program, tiling-program, and annotation-appearance program cache entries when those sources change, even if the invalidation remains tile-scoped. Rust SDK, C/Python/WASM/.NET/Java, and server source surfaces now propagate a render-invalidation plan from transaction apply output to cache-owning callers; Rust cache owners can parse direct plan JSON or SDK envelopes with `RenderInvalidationCachePlan` and apply exact or conservative mutations to `RenderDocumentCache`, with unknown nested refs forcing conservative reset. Display-list source caches are still page/dpi/revision scoped and raster tile caches carry full contract identity, but broader transaction write-set classification across arbitrary shared resources, external runtime matrices, and remaining conservative page-level narrowing are not complete.
3. **Progressive implementation is still not the full viewer scheduler:** lifecycle, structured fallback reporting, publication identity, bounded viewport and dirty-region obsolete-publication reporting, selective dirty-tile rescheduling, source-session tile-publication acceptance/rejection, source-level adjacent-page prefetch preview, bounded viewer queue preview JSON, source-level viewer queue execution JSON for owned current-page tiles, bounded adjacent-page child-session prefetch execution, source-level callback dispatch JSON with terminal suppression, C callback-pointer dispatch, and Python/WASM/.NET/Java synchronous callback helpers are active, but external viewer runtime matrices and broader queue policy remain incomplete.
4. **Cache policy is still mixed:** Byte-charged raw image, scaled image, SMask group, mesh-shading, Form XObject program, tiling-pattern program, transformed path clip-node, font-byte, font-resolver, glyph-outline, device glyph-mask, glyph-mask atlas page, Type 3 parsed geometry program, Type 3 parsed CharProc program, Type 3 mask, Type 3 rendered-glyph, path fill-mask, path stroke-mask, and retained display-list caches account bytes where applicable, use deterministic cache caps, and enforce aggregate `RenderResourceBudget.max_cache_bytes` cleanup when render state returns to `RenderDocumentCache` where applicable; page-scoped artifact pruning also exists for several retained resources. Direct CPU path fill/stroke mask caches refresh recency on hits, correct byte charges on key replacement, and evict least-recently-used masks one at a time instead of clearing the complete cache under pressure. Separation/DeviceN tint-transform outputs now use a thread-local entry/byte-capped LRU keyed by source document hash/length, resolved function fingerprint, and exact tint input bits, with metrics exposed in `ColorReport`. Persistent `ClipDag` intern tables now self-prune transitive unreferenced subgraphs behind a default node cap while preserving live save/restore/composite handles, and active per-render intern/pruning counters are serialized in `RenderContractTelemetryReport`. Transparent-page-group decisions use entry-capped LRU admission, runtime/server capabilities expose structured cache-pressure policy, and Rust/server/C/Python/WASM/.NET/Java contract report routes or source APIs expose one-shot per-render cache counters including path clip-node, glyph-atlas, and active clip-DAG stats; CLI `render-corpus` exposes retained display-list, annotation-appearance program, path clip-node, glyph-atlas, and active clip-DAG cache stats; external runtime telemetry remains an architectural resource-bound gap.
5. **Backend plan and complete caller surface ownership are still incomplete:** `RenderContract` and CLI raw surfaces now validate caller-owned raster layouts through the engine, but `CpuRenderDevice`/`PixelBuffer` are still internal execution constructs and there is no complete backend-neutral surface interface for every binding and policy field.
