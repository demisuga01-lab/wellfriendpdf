# Prompt 27 release fuzz and CI architecture

Prompt 27 adds durable release fuzz tooling instead of relying only on ad hoc local runs.

Scripts:

- `scripts/release_fuzz_matrix.py` builds the fuzz target inventory.
- `scripts/release_fuzz_runner.py` runs cargo-fuzz targets one at a time with bounded
  memory, time, corpus, and artifact paths.
- `scripts/minimize_fuzz_crash.py` wraps cargo-fuzz minimization.
- `scripts/promote_fuzz_seed.py` promotes legal minimized seeds into `fuzz/corpus/<target>/`.

Workflow:

- `.github/workflows/release-fuzz.yml` provides manual and scheduled release fuzz runs.
- Existing PR fuzz remains short; multi-hour fuzzing is reserved for scheduled/manual
  release tiers.

Policy:

- PR smoke: build and short replay/smoke only.
- Nightly: time-boxed release-critical target fuzzing and artifact upload.
- Release/VPS: parser target build and smoke, plus the high-priority parser long campaign.
- Prompt 25B low-memory posture remains the baseline for serial/bounded operation:
  dev fuzz build, no incremental compilation, high codegen units, bounded input, and
  one target at a time.
- For this Prompt 27 VPS run, the user approved a higher 16 GiB process-tree RSS
  cap per fuzz process while retaining the 32 GiB total Wellfriend budget. The
  runner does not use virtual-address `RLIMIT_AS` for ASan cargo-fuzz binaries.

Crashes, hangs, timeouts, OOMs, and sanitizer findings are release blockers until
classified, minimized where possible, fixed or regression-tested, and rerun.
