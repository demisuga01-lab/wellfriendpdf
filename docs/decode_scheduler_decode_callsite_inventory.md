# Decode Scheduler Decode Call-Site Inventory

Decode Scheduler audited non-render decode users after the Codec Boundary renderer scheduler
work. The machine-readable inventory is generated by:

```powershell
python scripts\decode_scheduler_codec_closeout.py
```

Primary artifact:

- `target/decode_scheduler-codec-closeout/decode-callsite-inventory.json`

Summary for the current repository state:

| Status | Count | Meaning |
| --- | ---: | --- |
| `scheduler_covered` | 16 | Decode path uses scheduler memory-token admission and `DecodeLimits`. |
| `metadata_only` | 4 | Path inspects dictionaries/object metadata and does not force stream decode. |
| `already_covered` | 3 | Renderer/OCR-prep image generation paths were covered by Codec Boundary. |
| `unsupported_reported` | 1 | Unsafe native backend posture remains denied and publicly reported. |

Important real call sites:

- `crates/engine/src/filters.rs`: raw stream and filter-chain decoding route through limits-aware scheduler admission.
- `crates/engine/src/engine.rs`: text extraction page-content streams, image XObject extraction, and inline image extraction use scheduler admission.
- `crates/engine/src/images/decoder.rs`: image decode helpers have limits-aware variants for XObject and inline image callers.
- `crates/engine/src/attachments.rs`: embedded-file extraction has a limits-aware scheduled path.
- `crates/engine/src/parser_report.rs`: `include_decode` probes each stream through scheduler diagnostics and preserves object-id order.

Metadata-only paths include active-content security scanning, standards-profile
inspection, attachment listing, and image inventory before extraction. They are
classified metadata-only because they do not request decoded stream bytes.
